# Домашняя работа по Java

## Отчёт о профилировании CPU

### Цель

Сравнить эндпоинты `GET /api/messages/nplus1` и `GET /api/messages/optimized` с помощью Java Flight Recorder (JFR).

### Подготовка и методика

- Приложение запускалось командой `./gradlew bootRun` с базой H2 в режиме in-memory.
- Задача `./gradlew runTestDataInitializer` добавляла 100 тестовых сообщений от 10 авторов. При запуске приложение также добавляет 3 примера.
- Перед записью профиля на каждый эндпоинт отправлялось по 100 запросов для прогрева и исключения из замера запуска приложения и первой компиляции JIT.
- Для каждого эндпоинта отдельно записывался профиль JFR (`settings=profile`) во время 1 000 последовательных GET-запросов.

### Результаты

| Эндпоинт | Запросы | Записи SQL-лога Hibernate | Длительность JFR |
| --- | ---: | ---: | ---: |
| `/api/messages/nplus1` | 1 000 | около 11 000 (зафиксировано 11 023) | около 17 с |
| `/api/messages/optimized` | 1 000 | 1 000 | около 16 с |

Эндпоинт N+1 сначала выполнял запрос сообщений, а затем дополнительные запросы для лениво загружаемых авторов. Оптимизированный эндпоинт загружал сообщения и авторов одним запросом с `JOIN FETCH`. При 10 разных авторах это примерно 11 запросов на один вызов против 1 запроса.

### Интерпретация профиля CPU

В списке наиболее часто попадавших в CPU-сэмплы методов преобладал код Spring, Hibernate и сериализации HTTP-ответа. Ни одна запись не показала явный CPU-hotspot в коде приложения; количество CPU-сэмплов было небольшим, поэтому по этому запуску нельзя уверенно утверждать, насколько изменилось именно CPU-время. Наиболее наглядно измеренная разница — объём запросов к базе данных. N+1 создаёт существенно больше работы для БД, что может увеличить задержки и нагрузку на CPU при более высокой нагрузке, хотя локальный запуск с H2 не выявил отдельного доминирующего CPU-hotspot.

### Как запустить профилирование

Нужны JDK-инструменты `jcmd` и `jfr`, `curl` и Python 3. Сначала запустите приложение:

```bash
./gradlew bootRun
```

Затем в другом терминале выполните:

```bash
./scripts/profile_endpoints.sh
```

Сценарий подготовит данные и снимет отдельный профиль для каждого эндпоинта. JFR-файлы и HTML-отчёт с flame graph появятся в `profiling-artifacts/`. Откройте `profiling-artifacts/index.html` в браузере. Число запросов можно изменить:

```bash
REQUESTS=2000 WARMUP_REQUESTS=200 ./scripts/profile_endpoints.sh
```

Каждый запуск сохраняется в отдельную папку с датой и временем. H2 работает в памяти, поэтому после перезапуска приложения снова запустите сценарий.
